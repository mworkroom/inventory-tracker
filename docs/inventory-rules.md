# Inventory Tracker 운영·계산 규칙

> - 상태: 확정 규칙의 단일 기준 문서
> - 최초 작성: 2026-08-25
> - 마지막 규칙 결정 및 코드 대조: 2026-08-31
> - 구현 상태: 로컬 2단계 화면·계산 전환과 운영 DB migration 적용까지 완료했으며 프런트 배포와 기존 호환 필드 제거는 아직 하지 않음

이 문서는 Inventory Tracker가 기록을 해석하고 재고·소비·구매 시점을 계산하는 기준을 한곳에 모은다. 앞으로 규칙을 바꿀 때는 이 문서를 먼저 고친 뒤 코드·테스트·화면 설명·관련 문서를 같은 규칙에 맞춘다.

현재 구현과 이 문서가 다르면 단순히 화면 문구만 맞추지 않는다. 먼저 어느 쪽을 유지할지 결정하고, 확정된 규칙을 이 문서와 구현에 함께 반영한다.

## 1. 앱의 기본 전제

### 1.1 개인 재고 관리 앱이다

- 앱의 기준 사용자는 J님 한 명이다.
- 재고 수량은 집에 실제로 남은 공동 재고의 수량이지만, 사용 주기·소비량·소진 예상·구매 추천은 J님 한 명의 소비 속도로 환산한다.
- 화면에 매번 `1인 기준`이라고 표시할 필요는 없다. 이 앱의 모든 계산이 개인 소비 기준이라는 사실을 전역 규칙으로 둔다.

### 1.2 함께 사용한 인원은 관찰값을 보정하는 정보다

- 개봉형 제품의 `사용 인원`은 그 제품 한 개를 실제로 함께 사용한 사람 수다.
- 사용 인원이 2명이라고 해서 앱의 기준 사용자가 2명으로 바뀌지는 않는다.
- 완료된 사용 기간에 사용 인원을 곱해 1인 환산 사용 기간을 구한다.

```text
1인 환산 사용 기간 = 실제 사용 기간 × 실제 사용 인원
```

예: 1L 올리브오일을 2명이 31일 동안 사용했다면 1인 환산 사용 주기는 약 62일이다.

### 1.3 실제 사용 근거를 우선한다

소비 속도와 소진 시점을 판단할 때의 우선순위는 다음과 같다.

1. 실제 사용 기록: 완료된 개봉–소진 주기 또는 수량형 사용 기록
2. 실제 사용 기록이 계산 가능한 수준에 이르기 전의 회상 소비 기준
3. 소비 속도 근거가 없을 때의 재고 수량 기준 알림

구매 기록은 가격·구매처·구매 간격·비축 행동을 이해하는 참고 자료다. 구매량을 실제 사용량으로 간주하거나 소비 속도와 소진일을 만드는 근거로 사용하지 않는다.

회상 소비 기준은 최초 예측을 돕는 임시 근거일 뿐 실제 사용 표본이나 재고 원장이 아니다. 실제 사용 기록만으로 계산할 수 있게 되는 즉시 실제 사용 근거가 회상 기준을 대체한다.

### 1.4 사실은 기록하고 패턴은 앱이 계산한다

- J님이 직접 입력하는 값은 제품명·용량·단위 같은 제품 사실과 구매·입고·사용·개봉·소진 같은 실제 사건이다.
- 소비 속도, 연간 필요량, 월별 소비 분포와 계절성은 실제 기록에서 앱이 계산한다.
- `사용 월`이나 `활성 월`처럼 관찰 결과로 알 수 있는 패턴을 제품 설정으로 미리 입력하지 않는다.
- 반복되는 세일의 월·일, 구매처, 행사명과 안전 재고처럼 앞으로의 구매 계획에 관한 값은 필요할 때만 직접 입력할 수 있다.

### 1.5 첫 실제 주기부터 추정하고 스스로 보정한다

- 완료된 실제 사용 주기 1회가 생기면 소비 속도와 소진일의 최초 추정치를 만든다.
- 1회 기준 결과는 사용할 수 없는 `학습 중`이 아니라 표본이 적은 `임시 추정`이다.
- 기록이 추가되면 최근 표본의 중앙값으로 기존 추정치를 자동 보정한다.
- 실제 기록이 쌓이기 전에는 선택적으로 등록한 회상 소비 기준으로 예측을 시작할 수 있다.
- 과거 기록을 모두 복원하는 일은 앱 사용의 선행 조건이 아니다. 정확한 최근 관찰 1회가 불확실하게 복원한 과거 여러 건보다 우선한다.

## 2. 기록의 의미

| 기록 | 의미 | 현재 재고 변경 | 주된 계산 용도 |
| --- | --- | ---: | --- |
| 구매 | 주문하거나 결제한 사실 | 변경하지 않음 | 구매 간격, 가격·구매처·구매 이력 |
| 입고 | 물건이 실제 재고에 들어온 사실 | 증가 | 현재 재고 원장 |
| 사용 | 수량형 제품을 실제로 사용한 사실 | 감소 | 현재 재고, 수량형 소비 속도 |
| 개봉 | 개봉형 제품 한 개를 사용하기 시작한 사실 | 변경하지 않음 | 진행 중 사용 주기 |
| 소진 | 개봉한 제품 한 개를 다 쓴 사실 | 정확히 1개 감소 | 현재 재고, 완료된 사용 주기 생성 |
| 재고 정정 | 확인한 실제 재고를 기준값으로 다시 설정 | 입력값으로 교체 | 원장 기준점 복구 |

### 2.1 구매와 입고는 별개다

- 구매했다고 자동으로 재고가 늘지 않는다.
- 배송받거나 집에 가져온 시점에 입고를 따로 기록해야 재고가 늘어난다.
- 구매 기록을 수정하거나 삭제해도 현재 재고는 바뀌지 않는다.
- 입고일은 구매 주기 계산에 포함하지 않는다.

### 2.2 재고 미설정과 재고 0은 다르다

- `재고 미설정`은 아직 기준 재고를 입력하지 않은 상태다.
- `재고 0`은 재고를 추적한 결과 실제로 0인 상태다.
- 최초 입고 또는 최초 재고 설정이 있어야 수량 기반 재고 판단을 시작한다.

### 2.3 `사용`과 `재고 정정`은 입력값의 의미가 다르다

`사용`은 수량형 제품에서 실제로 소비한 양을 기록하는 행동이다.

- 입력값은 `사용한 수량`이다.
- 현재 재고에서 입력값만큼 차감한다.
- 소비 속도를 학습하는 실제 사용 근거에 포함한다.
- 현재 남은 수량을 맞추기 위한 목표값을 입력하지 않는다.

`재고 정정`은 실물을 확인해 지금 남은 재고를 절대값으로 다시 설정하는 행동이다.

- 입력값은 `현재 실제로 남은 수량`이다.
- 기존 재고에서 얼마나 늘거나 줄었는지가 아니라 정정 후 재고 자체를 입력한다.
- 실제 사용 기록으로 보지 않으므로 소비 속도 학습에는 포함하지 않는다.
- 처음 재고 추적을 시작하거나, 누락된 기록 때문에 앱 수량과 실물이 달라졌거나, 사용량은 모르지만 현재 잔량은 확실할 때 사용한다.

| 확인한 사실 | 행동 | 입력값 |
| --- | --- | --- |
| 앱 재고가 정확한 상태에서 1개를 실제로 사용했다 | 사용 | `1` |
| 앱에는 10개가 있고, 그 뒤 정확히 3개를 사용한 사실을 안다 | 사용 | `3` |
| 앱에는 10개라고 나오지만 실물을 세니 7개이고 차이의 원인은 확실하지 않다 | 재고 정정 | `7` |
| 과거 구매 기록을 입력한 뒤 현재 실물을 세니 7개다 | 재고 정정 | `7` |

주기적으로 실물 재고를 확인했을 때 앱 수량과 차이가 나면 원인을 아는지가 행동을 가른다. 그 차이가 실제 사용량이라고 확실히 아는 경우에는 `사용`으로 기록하고, 원인이 불분명하면 `재고 정정`으로 현재 수량만 맞춘다.

예: 쉬크 인튜이션 면도날을 과거에 총 20개 샀고 현재 7개가 남았더라도 `사용 13개`를 새로 만들지 않는다. 과거 구매는 현재 재고의 시작값이 아니며, 13개를 언제 사용했는지도 알 수 없기 때문이다. 이 경우 `재고 정정 7개`로 현재 기준점을 잡고, 그다음부터 실제로 사용한 수량을 `사용`으로 기록한다.

개봉형 제품에는 수량형 `사용` 기록을 쓰지 않는다. 개봉형은 `개봉`과 `소진`으로 사용을 기록하며, 재고 개수가 실제와 달라졌을 때만 `재고 정정`을 사용한다.

## 3. 기본 사용 기록 방식과 재고 단위

- 제품에는 현재 기본으로 사용할 기록 방식 하나만 둔다. 이 값은 제품의 정체성이나 재고 단위를 분류하는 값이 아니다.
- `사용량 차감`은 사용할 때마다 소비한 수량을 기록하고, `개봉–소진 주기`는 제품 한 개의 시작일과 종료일을 기록한다.
- 재고는 `병`, `통`, `봉`, `인분`, `개`처럼 실제로 세고 구매하는 실용 단위로 유지한다.
- 제품 한 개의 ml·g 같은 용량은 소비량을 함께 보고 싶을 때 쓰는 선택적 보조 정보이며, 모든 재고를 무게나 부피 단위로 바꾸지 않는다.
- 기본 사용 기록 방식은 한 시점에 하나만 활성화한다. 방식 변경은 진행 중인 개봉 주기가 없을 때 미래 날짜부터 적용하며, 변경 전 기록의 의미와 통계 이력은 그대로 보존한다.

### 3.1 사용량 차감 방식

- 달걀·닭안심처럼 사용할 때마다 수량을 줄일 수 있는 제품에 사용한다.
- 사용 기록은 현재 재고를 입력 수량만큼 줄인다.
- 소진 속도는 최근 사용일 최대 8개의 기록을 기준으로 계산한다.
- 같은 날 여러 번 사용한 양은 그날의 총사용량으로 합친다.
- 서로 다른 사용일이 최소 2일 있어야 실제 사용 속도를 계산한다.
- 최근 사용일 사이 간격의 중앙값을 대표 간격으로, 일별 사용량의 중앙값을 대표 사용량으로 사용한다.

```text
1단위당 예상 사용 일수 = 대표 사용 간격 ÷ 대표 사용량
예상 잔여 사용 일수 = 현재 재고 × 1단위당 예상 사용 일수
```

### 3.2 개봉–소진 주기 방식

- 오일·샴푸처럼 한 개를 개봉하고 다 쓴 날을 기록하는 제품에 사용한다.
- 재고 개수는 정수로 관리한다. 제품 용량과 용량 단위는 용량 소비량까지 계산할 때만 사용한다.
- 개봉해도 재고 개수는 줄지 않는다. 개봉한 한 개도 현재 재고에 포함된다.
- 소진할 때 현재 재고에서 정확히 1개를 차감하고 완료된 사용 주기를 만든다.
- 동시에 진행 중인 개봉 기록은 제품당 하나만 둘 수 있다.
- 완료된 최근 주기 최대 5개의 1인 환산 기간 중앙값을 대표 사용 주기로 사용한다.
- 진행 중인 개봉 주기를 먼저 끝내야 기본 사용 기록 방식을 바꿀 수 있다. 변경은 과거 기록을 재해석하지 않는다.

## 4. 개봉형 사용 주기 계산

### 4.1 한 주기의 환산

개봉일과 소진일을 모두 포함해 실제 사용 기간을 센다.

```text
1인 환산 주기 = 실제 사용 일수 × 사용 인원 × 용량 비율
용량 비율 = 현재 제품 용량 ÷ 당시 제품 용량
```

- 현재와 과거의 용량 단위가 같을 때만 용량을 보정한다.
- 과거 용량 정보가 없거나 단위가 다르면 용량 비율은 1로 본다.
- 대표 사용 주기는 최근 완료 주기 최대 5개의 환산값 중앙값이다.

예: 500ml 제품을 1명이 30일 사용했고 현재 제품이 1L라면, 현재 1L 기준 환산 주기는 약 60일이다.

### 4.2 사용 인원이 섞인 기록

각 완료 주기를 먼저 1인 기준으로 바꾼 뒤 중앙값을 구한다.

예: 코코넛오일 기록이 아래와 같다면 두 기록은 같은 소비 속도를 뜻한다.

- 1명이 60일 사용 → 1인 환산 60일
- 2명이 30일 사용 → 1인 환산 60일

따라서 대표 사용 주기는 약 60일이다. 특정 한 주기의 인원수를 전체 기록에 일괄 적용하지 않는다.

### 4.3 현재 개봉 제품과 미개봉 재고

- 현재 개봉 제품의 경과량은 `활성 경과 일수 × 현재 사용 인원`으로 계산한다.
- 대표 1인 환산 주기에서 경과 인일을 빼 현재 개봉 제품의 잔여량을 추정한다.
- 나머지 미개봉 제품은 각각 대표 1인 환산 주기만큼 남은 것으로 본다.
- 현재 재고 전체의 예상 소진일은 현재 개봉 제품의 잔여 기간과 미개봉 재고의 기간을 합쳐 구한다.

## 5. 구매 주기 계산

### 5.1 구매 간격 통계에는 모든 구매 기록을 사용한다

- 실제 사용 기록의 유무와 관계없이 해당 제품의 모든 구매 기록을 구매 통계에 포함한다.
- 구매 기록 수, 구매일 수, 총구매 수량은 서로 다른 값이다.
- 같은 날짜에 여러 구매 기록이 있어도 구매 기록 수와 총구매 수량에는 모두 포함한다.
- 구매 간격을 계산할 때만 같은 날짜를 하나의 구매일로 합친다.
- 날짜순 구매 간격 중 최근 최대 7개의 중앙값을 대표 구매 간격으로 사용한다.

```text
다음 구매 예상일 = 마지막 구매일 + 대표 구매 간격
```

- 같은 날짜·같은 쇼핑몰의 구매 기록은 중복 가능성을 경고한다. 실제 별도 구매가 맞다고 확인하면 저장할 수 있다.
- 입고 기록은 구매 간격에 포함하지 않는다.

### 5.2 구매 간격은 사용 속도가 아니다

- 구매 간격은 실제로 언제 다시 샀는지를 보여주는 일정 신호다.
- 여러 개를 한꺼번에 사거나 세일 때 미리 사면 실제 소비 주기와 달라질 수 있다.
- 실제 사용 기반 소진 예측이 있으면 구매 간격은 별도의 재구매 경고를 만들지 않는다.
- 실제 사용 기반 소진 예측이 없을 때만 다음 구매 예상일을 보조 신호로 사용한다.
- 정기 세일 일정이 있으면 다가오는 세일 기회 신호를 구매 간격보다 우선한다.

## 6. 과거 기록의 활용 범위

### 6.1 과거 구매 기록은 구매 행동의 근거다

- 과거 구매일·수량·용량·가격·구매처는 구매 간격, 가격 변화, 세일 비축 행동을 이해하는 데 사용한다.
- 구매한 양을 모두 소비했다고 가정해 실제 소비량을 복원하지 않는다.
- 과거 구매량과 현재 재고의 차이를 임의의 사용 기록으로 만들지 않는다.
- 과거 구매 기록은 실제 사용 기록이 없더라도 소비 속도·연간 필요량·소진일의 대체 근거가 되지 않는다.

### 6.2 회상 소비 기준은 실제 기록 전의 임시 출발점이다

- 정확한 과거 사건을 여러 건 복원하는 대신, 기억하는 한 구간의 대략적인 시작일·종료일과 총소비량을 제품별로 하나만 등록할 수 있다.
- 사용량 차감 방식은 해당 구간의 총사용량을, 개봉–소진 주기 방식은 제품 한 개의 대략적인 개봉일과 소진일을 저장한다.
- 회상 기준은 소비 속도와 소진일의 임시 추정에만 사용한다. 현재 재고를 바꾸거나 실제 사용 표본 수를 늘리거나 계절성 분석에 포함하지 않는다.
- 실제 사용량 차감 기록이 서로 다른 날짜에 2일 이상 생기거나 완료된 개봉–소진 주기가 1회 생기면 실제 사용 방식만으로 계산할 수 있으므로 회상 기준은 자동으로 예측 우선순위에서 제외한다.
- 제외된 회상 기준은 당시 판단의 근거를 확인할 수 있도록 상세 정보에 보존한다.

### 6.3 정확한 과거 사용 기록만 실제 사용 근거가 될 수 있다

- 과거의 사용일 또는 개봉일·소진일을 실제 사실로 알고 있을 때만 실제 사용 기록으로 입력할 수 있다.
- 기억에 의존해 사용 기간이나 사용량을 추측한 값은 표본 수를 늘리기 위한 학습 자료로 만들지 않는다.
- 과거 사용 기록 입력은 선택 사항이며, 미래의 실제 기록을 시작하기 위한 선행 작업이 아니다.
- 과거와 미래를 날짜로 구분하기보다 기록의 의미와 신뢰도를 구분한다. 같은 의미와 품질의 실제 사용 기록이면 날짜와 관계없이 같은 근거로 취급할 수 있다.

## 7. 계절성 자동 분석

### 7.1 계절성은 제품 설정이 아니라 관찰 결과다

- 수동 `사용 월` 또는 `활성 월` 설정을 제거한다.
- 실제 사용·개봉·소진 기록의 날짜별·월별 분포를 바탕으로 사용이 집중되거나 멈추는 시기를 앱이 자동으로 발견한다.
- 앱에서 관찰한 실제 사용 기록이 1건이라도 생기면 해당 기록을 월별 실제 통계에 표시한다. 회상 소비 기준은 이 통계에 포함하지 않는다.
- 처음 발견한 월별 차이는 상세 통계에 원자료로 보여주되, 곧바로 반복되는 계절 패턴이라고 단정하지 않는다.
- 계절성은 연간 필요량을 계산하기 위한 필수 입력이 아니라 `언제 많이 쓰는가`를 설명하는 분석 결과다.

### 7.2 연간 필요량은 수동 계절 월과 분리한다

- 연간 필요량은 실제 사용 근거에서 확인한 총소비량 또는 소비 속도를 연간 기준으로 환산한다.
- 계산 과정의 분모로 J님이 선택한 사용 월 수를 사용하지 않는다.
- 완전한 1년 관찰이 있으면 최근 1년의 실제 총소비량을 가장 직접적인 연간 근거로 사용할 수 있다.
- 관찰 기간이 1년보다 짧으면 현재 소비 속도가 이어진다는 가정의 임시 추정으로 표시하며, 계절 사용 제품에서는 오차가 클 수 있음을 숨기지 않는다.

### 7.3 예측 반영에는 더 강한 근거가 필요하다

- 한 번의 완료 주기는 기본 소비 속도와 현재 사용 중인 제품의 소진을 추정하는 데 사용할 수 있다.
- 계절성을 예측에 반영하려면 앱이 직접 관찰한 실제 사용 기록으로 완전한 달력 12개월을 채우고, 실제 소비 근거가 최소 2건 있어야 한다.
- 최근 완전한 12개월에서 연속 3개월 이동평균들을 비교했을 때 최고 이동평균이 최저 이동평균의 2배 이상이어야 계절 차이가 충분하다고 본다.
- 이 조건을 충족하기 전에는 소진일과 세일 구매 추천에 계절성을 반영하지 않는다. 예측은 계절 보정 없는 기본 소비 속도를 사용하며 `임시 추정`으로 표시한다.
- 조건을 충족한 뒤에도 계절성은 연간 필요량 총합을 늘리거나 줄이지 않고, 같은 연간 총량을 월별로 재분배하는 데만 사용한다.
- 회상 소비 기준과 구매 기록은 관찰 기간, 표본 수, 월별 가중치 계산에서 모두 제외한다.

## 8. 소진 예측과 확인 필요 신호

### 8.1 소진일 근거

소진일의 소비 속도 근거는 `실제 사용`, 즉 완료 주기 또는 수량형 사용 기록이다.

과거 구매 간격으로 만든 날짜는 소진일이 아니라 `다음 구매 예상일`이다.

### 8.2 알림 기준

- 실제 사용으로 소진일을 계산할 수 있으면, 남은 일수가 제품의 알림 일수 이하일 때 확인 필요로 본다.
- 소진일을 계산할 수 없을 때만 현재 재고가 재고 알림 수량 이하인지 확인한다.
- 신뢰할 수 있는 소진일이 있는 동안에는 수량 기준 알림을 중복 적용하지 않는다.
- 등록한 정기 세일 일정이 알림 기간 안에 들어오면 구매 확인 신호를 표시한다.
- 소진일 근거가 없고 다음 구매 예상일이 알림 기간 안에 들어오면 구매 확인 신호를 표시한다.

## 9. 월·연간 소비 통계

- 실제 사용 기록으로 소비 속도를 구할 수 있을 때만 소비 통계를 계산한다.
- 과거 구매량은 월·연간 소비 통계의 대체 근거로 사용하지 않는다.
- 개봉형의 용량 소비 속도는 `현재 제품 용량 ÷ 대표 1인 환산 주기`다.
- 수량형의 소비 속도는 최근 사용 기록으로 구한 `1단위당 예상 사용 일수`를 역산한다.
- 월평균은 평균 한 달 30.4375일, 연간은 365.25일을 기준으로 환산한다.
- 개봉형은 용량과 제품 개수를 함께 표시할 수 있다.
- 완료 주기 1회부터 임시 추정치를 표시하고 표본 수 또는 신뢰도 단계를 함께 보여준다.
- 충분한 계절 관찰 전의 월·연 환산량은 현재 소비 속도가 계속된다는 가정이며, 자동 발견한 계절성이 예측 근거로 승격된 뒤에는 해당 패턴으로 보정할 수 있다.

## 10. 정기 세일 일정과 구매 추천

### 10.1 정기 세일 일정

- 제품마다 필요한 만큼 여러 정기 세일 일정을 등록할 수 있다.
- 각 일정에는 반복되는 월·일, 구매처와 행사명을 저장한다. 연도는 저장하지 않는다.
- 월·일은 세일 시작일을 정확히 보장하는 날짜가 아니라 `3월 초`, `블랙프라이데이 무렵` 같은 구매 기회의 기준점이다.
- 기준일이 지난 뒤에도 그 달 말까지는 현재 진행 중인 구매 기회로 본다. 다음 달부터 다음 등록 일정을 찾는다.
- 등록한 일정은 모두 J님이 실제 구매를 고려하는 기회다. 세일 추적이 필요 없는 상시 구매 제품에는 일정을 만들지 않는다.
- 제품의 `알림 일수`를 기준으로 다가오는 일정의 확인 시점을 정한다.

### 10.2 세일 구매량과 임시 구매량

세일 구매 추천은 현재 구매 기회에서 그다음 등록된 구매 기회까지 필요한 실제 소비량과 안전 재고를 확보하는 방식으로 계산한다. 별도의 `확보할 개월 수`를 입력하지 않는다.

```text
세일일 예상 재고
= 현재 재고 - 오늘부터 세일일까지의 예상 소비량

추천 구매 수량
= 올림(현재 구매 기회부터 다음 등록 구매 기회까지의 예상 소비량
     + 안전 재고
     - 세일일 예상 재고)
```

- 결과가 음수이면 0으로 본다.
- 충분한 관찰로 계절 패턴이 예측 근거가 된 제품만 월별 계절 가중치를 반영한다.
- 그 전에는 계절 보정 없는 기본 소비 속도를 사용하며 결과가 임시 추정임을 표시한다.
- 추천 수량은 구매 개수 기준 정수로 올림한다.
- 현재 재고가 다음 세일까지 버티지 못하면 `지금 살 최소 수량`을 세일 때 살 추천 수량과 분리해 표시한다. 임시 구매는 다음 세일까지 버티기 위한 최소량만 제안한다.

## 11. 기록 날짜와 정정 규칙

### 11.1 날짜

- 업무 기록 날짜는 오늘 또는 과거만 허용한다.
- 소진일은 개봉일보다 빠를 수 없다.
- 개봉일과 소진일은 모두 사용 기간에 포함한다.
- 데이터베이스의 업무 기준 날짜는 Asia/Seoul을 사용한다.
- 날짜는 내부적으로 ISO 형식으로 저장하고 화면에서는 미국식 월/일/연도 형식으로 표시한다.

### 11.2 재고 원장 정정

- 입고 또는 수량형 사용 기록의 수량을 수정·삭제하면 그 시점 이후 재고 원장을 시간순으로 다시 계산한다.
- 같은 시각의 기록은 생성 순서를 유지한다.
- 재고 정정은 증감량이 아니라 그 시점의 실제 재고를 나타내는 절대 기준점이다.
- 원장을 다시 계산해 음수 재고가 생기거나 개봉·소진 순서가 성립하지 않으면 정정을 거부한다.

### 11.3 개봉·소진 주기 정정

- 진행 중인 개봉 기록의 개봉일과 사용 인원을 고치면 제품 상태와 연결된 개봉 이벤트를 함께 고친다.
- 완료된 사용 주기의 개봉일·소진일·사용 인원은 통계 근거로서 수정할 수 있다.
- 동일 제품에 개봉일과 소진일이 모두 같은 완료 주기를 중복 저장하지 않는다.
- 완료된 사용 주기를 수정하거나 삭제해도 이미 기록된 소진 이벤트와 재고 1개 차감은 되돌리지 않는다. 재고가 틀렸다면 재고 원장을 별도로 정정한다.

## 12. 제품 숨기기와 삭제

- 목록에서 숨기기는 모든 재고·사용·구매 기록을 유지한 채 기본 목록에서만 제품을 감춘다.
- 현재 개봉해 사용 중인 제품은 소진 처리 전까지 숨길 수 없다.
- 숨긴 제품은 다시 표시할 수 있다.
- 영구 삭제는 실제 사용·완료 주기·구매 기록이 없는 제품에만 허용한다.
- 최초 재고 기준 기록 하나만 있는 미사용 제품은 영구 삭제할 수 있다.
- 기록이 있는 제품은 삭제하지 않고 숨긴다.

## 13. 현재 모델의 한계

아래 항목은 확정 규칙이라기보다 현재 데이터 모델로 정확히 처리할 수 없는 범위다. 다른 문서와 코드를 정비할 때 별도 결정이 필요하다.

### 13.1 수량형 공동 사용은 인원 보정이 없다

수량형 사용 기록에는 사용 인원이 없다. 따라서 엄마와 함께 사용해 재고 감소가 빨라진 기간을 J님 한 명의 소비 속도로 되돌릴 수 없다. 현재 계산은 모든 수량형 사용 기록을 개인 소비로 간주한다.

### 13.2 과거 구매 기록만으로 실제 소비를 복원할 수 없다

과거 구매량에는 당시 재고, 비축 여부, 실제 사용 시기와 사용 인원 정보가 없다. 따라서 구매 기록을 소비량으로 환산하지 않고 구매 행동의 참고 자료로만 사용한다.

### 13.3 제품 한 개 안의 실제 잔량은 측정하지 않는다

개봉형 제품의 현재 잔량은 대표 사용 주기와 경과 인일로 추정한다. 병 안의 실제 ml를 직접 기록하는 모델은 아니다.

### 13.4 동시에 여러 개를 개봉하는 상황은 지원하지 않는다

개봉형 제품은 제품당 진행 중 주기를 하나만 둔다. 같은 제품 여러 개를 동시에 서로 다른 인원이나 장소에서 사용하는 상황은 표현할 수 없다.

### 13.5 구매와 입고를 자동 연결하지 않는다

어떤 구매가 어떤 입고로 이어졌는지 연결하는 식별자는 없다. 구매 이력과 재고 원장은 의도적으로 독립되어 있다.

## 14. 규칙 변경 절차

규칙을 새로 정하거나 바꿀 때는 다음 순서를 따른다.

1. 이 문서에서 용어, 입력 의미, 계산 우선순위, 예외를 먼저 확정한다.
2. 기존 데이터에 미치는 영향과 마이그레이션 필요 여부를 확인한다.
3. 계산 코드와 데이터베이스 제약을 함께 수정한다.
4. 대표 사례와 경계 사례를 테스트로 고정한다.
5. 실제 화면의 결과와 설명 문구를 확인한다.
6. `CONTEXT.md`, README, ADR, 기존 요구사항 문서 등 관련 문서를 이 기준에 맞춘다.
7. 개발 로그에 변경 이유, 결정, 검증 결과, 남은 한계를 기록한다.

## 15. 대표 확인 사례

규칙 변경 후 최소한 아래 사례를 다시 확인한다.

- 1L 제품을 2명이 약 1개월 사용하면 1인 주기가 약 2개월로 계산되는가.
- 1인 사용 주기와 2인 사용 주기가 섞여도 각 기록을 개별 환산한 뒤 중앙값을 구하는가.
- 같은 날 여러 구매가 구매 건수에는 모두 포함되고 구매 간격에는 하루로만 포함되는가.
- 완료된 실제 사용 주기 1회가 생기면 `학습 중`을 벗어나 표본 1회의 임시 추정으로 표시되는가.
- 회상 소비 기준은 실제 기록 전의 임시 예측만 만들고, 차감 기록 2일 또는 완료 주기 1회가 생기면 예측 우선순위에서 제외되는가.
- 과거 구매 기록만으로 소비 속도·연간 필요량·소진일이 만들어지지 않는가.
- 구매 간격 통계는 실제 사용 기록이 있어도 모든 구매일로 계속 계산되는가.
- 구매 기록을 고쳐도 재고가 변하지 않고, 입고 기록을 고치면 이후 재고가 다시 계산되는가.
- 제품 편집 화면에 수동 사용 월 설정이 없고 실제 기록에서 월별 사용 분포가 자동 계산되는가.
- 계절 관찰이 충분하지 않을 때 상세 통계는 표시할 수 있어도 소진일과 세일 추천은 계절 보정하지 않는가.
- 완전한 12개월, 실제 소비 근거 2건, 3개월 이동평균 2배 조건을 모두 충족할 때만 연간 총량을 유지한 채 월별 예측이 재분배되는가.
- 여러 정기 세일 일정 중 현재 월 말까지 유효한 구매 기회와 그다음 구매 기회를 찾아 추천량을 계산하는가.
- 다음 세일까지 재고가 부족할 때 지금 살 최소 수량과 세일 구매 추천량이 분리되는가.
- 완료 주기를 삭제해도 재고 차감이 자동 복구되지 않는가.
