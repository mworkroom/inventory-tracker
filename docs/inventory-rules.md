# Inventory Tracker 운영·계산 규칙

> - 상태: 현재 규칙의 단일 기준 문서
> - 최초 작성: 2026-08-25
> - 마지막 코드 대조: 2026-08-25

이 문서는 Inventory Tracker가 기록을 해석하고 재고·소비·구매 시점을 계산하는 기준을 한곳에 모은다. 앞으로 규칙을 바꿀 때는 이 문서를 먼저 고친 뒤 코드·테스트·화면 설명·관련 문서를 같은 규칙에 맞춘다.

현재 구현과 이 문서가 다르면 단순히 화면 문구만 맞추지 않는다. 먼저 어느 쪽을 유지할지 결정하고, 확정된 규칙을 이 문서와 구현에 함께 반영한다.

## 1. 앱의 기본 전제

### 1.1 개인 재고 관리 앱이다

- 앱의 기준 사용자는 J님 한 명이다.
- 재고 수량은 집에 실제로 남은 공동 재고의 수량이지만, 사용 주기·소비량·소진 예상·구매 추천은 J님 한 명의 소비 속도로 환산한다.
- 화면에 매번 `1인 기준`이라고 표시할 필요는 없다. 이 앱의 모든 계산이 개인 소비 기준이라는 사실을 전역 규칙으로 둔다.

### 1.2 함께 사용한 인원은 관찰값을 보정하는 정보다

- 개봉형 제품의 `사용 인원`은 그 제품 한 개를 실제로 함께 사용한 사람 수다.
- 사용 인원이 2명이라고 해서 앱의 기준 사용자가 2명으로 바뀌지는 않는다.
- 완료된 사용 기간에 사용 인원을 곱해 1인 환산 사용 기간을 구한다.

```text
1인 환산 사용 기간 = 실제 사용 기간 × 실제 사용 인원
```

예: 1L 올리브오일을 2명이 31일 동안 사용했다면 1인 환산 사용 주기는 약 62일이다.

### 1.3 실제 사용 근거를 우선한다

소비 속도와 소진 시점을 판단할 때의 우선순위는 다음과 같다.

1. 실제 사용 기록: 완료된 개봉–소진 주기 또는 수량형 사용 기록
2. 조건을 충족한 과거 구매량 기반 소비 추정
3. 과거 구매 간격 기반 다음 구매일 추정
4. 소비 속도를 계산할 수 없을 때의 재고 수량 기준 알림

구매 기록은 실제 사용 기록을 덮어쓰지 않는다.

## 2. 기록의 의미

| 기록 | 의미 | 현재 재고 변경 | 주된 계산 용도 |
| --- | --- | ---: | --- |
| 구매 | 주문하거나 결제한 사실 | 변경하지 않음 | 구매 간격, 보조 소비 추정, 가격·구매 이력 |
| 입고 | 물건이 실제 재고에 들어온 사실 | 증가 | 현재 재고 원장 |
| 사용 | 수량형 제품을 실제로 사용한 사실 | 감소 | 현재 재고, 수량형 소비 속도 |
| 개봉 | 개봉형 제품 한 개를 사용하기 시작한 사실 | 변경하지 않음 | 진행 중 사용 주기 |
| 소진 | 개봉한 제품 한 개를 다 쓴 사실 | 정확히 1개 감소 | 현재 재고, 완료된 사용 주기 생성 |
| 재고 정정 | 확인한 실제 재고를 기준값으로 다시 설정 | 입력값으로 교체 | 원장 기준점 복구 |

### 2.1 구매와 입고는 별개다

- 구매했다고 자동으로 재고가 늘지 않는다.
- 배송받거나 집에 가져온 시점에 입고를 따로 기록해야 재고가 늘어난다.
- 구매 기록을 수정하거나 삭제해도 현재 재고는 바뀌지 않는다.
- 입고일은 구매 주기 계산에 포함하지 않는다.

### 2.2 재고 미설정과 재고 0은 다르다

- `재고 미설정`은 아직 기준 재고를 입력하지 않은 상태다.
- `재고 0`은 재고를 추적한 결과 실제로 0인 상태다.
- 최초 입고 또는 최초 재고 설정이 있어야 수량 기반 재고 판단을 시작한다.

### 2.3 `사용`과 `재고 정정`은 입력값의 의미가 다르다

`사용`은 수량형 제품에서 실제로 소비한 양을 기록하는 행동이다.

- 입력값은 `사용한 수량`이다.
- 현재 재고에서 입력값만큼 차감한다.
- 소비 속도를 학습하는 실제 사용 근거에 포함한다.
- 현재 남은 수량을 맞추기 위한 목표값을 입력하지 않는다.

`재고 정정`은 실물을 확인해 지금 남은 재고를 절대값으로 다시 설정하는 행동이다.

- 입력값은 `현재 실제로 남은 수량`이다.
- 기존 재고에서 얼마나 늘거나 줄었는지가 아니라 정정 후 재고 자체를 입력한다.
- 실제 사용 기록으로 보지 않으므로 소비 속도 학습에는 포함하지 않는다.
- 처음 재고 추적을 시작하거나, 누락된 기록 때문에 앱 수량과 실물이 달라졌거나, 사용량은 모르지만 현재 잔량은 확실할 때 사용한다.

| 확인한 사실 | 행동 | 입력값 |
| --- | --- | --- |
| 앱 재고가 정확한 상태에서 1개를 실제로 사용했다 | 사용 | `1` |
| 앱에는 10개가 있고, 그 뒤 정확히 3개를 사용한 사실을 안다 | 사용 | `3` |
| 앱에는 10개라고 나오지만 실물을 세니 7개이고 차이의 원인은 확실하지 않다 | 재고 정정 | `7` |
| 과거 구매 기록을 입력한 뒤 현재 실물을 세니 7개다 | 재고 정정 | `7` |

예: 쉬크 인튜이션 면도날을 과거에 총 20개 샀고 현재 7개가 남았더라도 `사용 13개`를 새로 만들지 않는다. 과거 구매는 현재 재고의 시작값이 아니며, 13개를 언제 사용했는지도 알 수 없기 때문이다. 이 경우 `재고 정정 7개`로 현재 기준점을 잡고, 그다음부터 실제로 사용한 수량을 `사용`으로 기록한다.

개봉형 제품에는 수량형 `사용` 기록을 쓰지 않는다. 개봉형은 `개봉`과 `소진`으로 사용을 기록하며, 재고 개수가 실제와 달라졌을 때만 `재고 정정`을 사용한다.

## 3. 제품 기록 방식

### 3.1 수량형

- 달걀·닭안심처럼 사용할 때마다 수량을 줄일 수 있는 제품에 사용한다.
- 사용 기록은 현재 재고를 입력 수량만큼 줄인다.
- 소진 속도는 최근 사용일 최대 8개의 기록을 기준으로 계산한다.
- 같은 날 여러 번 사용한 양은 그날의 총사용량으로 합친다.
- 서로 다른 사용일이 최소 2일 있어야 실제 사용 속도를 계산한다.
- 최근 사용일 사이 간격의 중앙값을 대표 간격으로, 일별 사용량의 중앙값을 대표 사용량으로 사용한다.

```text
1단위당 예상 사용 일수 = 대표 사용 간격 ÷ 대표 사용량
예상 잔여 사용 일수 = 현재 재고 × 1단위당 예상 사용 일수
```

### 3.2 개봉형

- 오일·샴푸처럼 한 개를 개봉하고 다 쓴 날을 기록하는 제품에 사용한다.
- 제품 용량과 용량 단위가 필요하며 재고 개수는 정수로 관리한다.
- 개봉해도 재고 개수는 줄지 않는다. 개봉한 한 개도 현재 재고에 포함된다.
- 소진할 때 현재 재고에서 정확히 1개를 차감하고 완료된 사용 주기를 만든다.
- 동시에 진행 중인 개봉 기록은 제품당 하나만 둘 수 있다.
- 완료된 최근 주기 최대 5개의 1인 환산 기간 중앙값을 대표 사용 주기로 사용한다.
- 제품의 기록 방식은 생성 후 바꾸지 않는다. 기존 원장과 통계 의미가 달라지는 일을 막기 위한 규칙이다.

## 4. 개봉형 사용 주기 계산

### 4.1 한 주기의 환산

개봉일과 소진일을 모두 포함해 실제 사용 기간을 센다. 계절 제품은 활성 월에 속한 날만 센다.

```text
1인 환산 주기 = 실제 활성 사용 일수 × 사용 인원 × 용량 비율
용량 비율 = 현재 제품 용량 ÷ 당시 제품 용량
```

- 현재와 과거의 용량 단위가 같을 때만 용량을 보정한다.
- 과거 용량 정보가 없거나 단위가 다르면 용량 비율은 1로 본다.
- 대표 사용 주기는 최근 완료 주기 최대 5개의 환산값 중앙값이다.

예: 500ml 제품을 1명이 30일 사용했고 현재 제품이 1L라면, 현재 1L 기준 환산 주기는 약 60일이다.

### 4.2 사용 인원이 섞인 기록

각 완료 주기를 먼저 1인 기준으로 바꾼 뒤 중앙값을 구한다.

예: 코코넛오일 기록이 아래와 같다면 두 기록은 같은 소비 속도를 뜻한다.

- 1명이 60일 사용 → 1인 환산 60일
- 2명이 30일 사용 → 1인 환산 60일

따라서 대표 사용 주기는 약 60일이다. 특정 한 주기의 인원수를 전체 기록에 일괄 적용하지 않는다.

### 4.3 현재 개봉 제품과 미개봉 재고

- 현재 개봉 제품의 경과량은 `활성 경과 일수 × 현재 사용 인원`으로 계산한다.
- 대표 1인 환산 주기에서 경과 인일을 빼 현재 개봉 제품의 잔여량을 추정한다.
- 나머지 미개봉 제품은 각각 대표 1인 환산 주기만큼 남은 것으로 본다.
- 현재 재고 전체의 예상 소진일은 현재 개봉 제품의 잔여 기간과 미개봉 재고의 기간을 합쳐 구한다.

## 5. 구매 주기 계산

### 5.1 구매 간격 통계에는 모든 구매 기록을 사용한다

- 실제 사용 기록의 유무와 관계없이 해당 제품의 모든 구매 기록을 구매 통계에 포함한다.
- 구매 기록 수, 구매일 수, 총구매 수량은 서로 다른 값이다.
- 같은 날짜에 여러 구매 기록이 있어도 구매 기록 수와 총구매 수량에는 모두 포함한다.
- 구매 간격을 계산할 때만 같은 날짜를 하나의 구매일로 합친다.
- 날짜순 구매 간격 중 최근 최대 7개의 중앙값을 대표 구매 간격으로 사용한다.

```text
다음 구매 예상일 = 마지막 구매일 + 대표 구매 간격
```

- 같은 날짜·같은 쇼핑몰의 구매 기록은 중복 가능성을 경고한다. 실제 별도 구매가 맞다고 확인하면 저장할 수 있다.
- 입고 기록은 구매 간격에 포함하지 않는다.

### 5.2 구매 간격은 사용 속도가 아니다

- 구매 간격은 실제로 언제 다시 샀는지를 보여주는 일정 신호다.
- 여러 개를 한꺼번에 사거나 세일 때 미리 사면 실제 소비 주기와 달라질 수 있다.
- 실제 사용 기반 소진 예측이 있으면 구매 간격은 별도의 재구매 경고를 만들지 않는다.
- 실제 사용 기반 소진 예측이 없을 때만 다음 구매 예상일을 보조 신호로 사용한다.
- 다음 세일일을 직접 입력한 경우에는 세일일 신호를 구매 간격보다 우선한다.

## 6. 과거 구매량 기반 소비 추정

구매 간격 통계와 구매량 기반 소비 추정은 서로 다른 계산이다.

### 6.1 언제 사용하는가

- 실제 사용 기록만으로 소비 속도를 계산할 수 있으면 구매량 추정을 사용하지 않는다.
- 실제 사용 근거가 부족할 때만 과거 구매량을 보조 소비 근거로 사용한다.
- 재고·사용 추적을 시작한 첫 이벤트보다 이전에 발생한 구매만 사용한다.
- 첫 재고·사용 이벤트와 같은 날 또는 그 이후의 구매는 구매량 기반 소비 추정에서 제외한다.
- 최초 과거 구매일부터 재고 추적 시작일까지 관찰 기간이 30일 이상이어야 소비 통계를 표시한다.

### 6.2 어떻게 계산하는가

- 수량형은 과거 총구매 개수를 활성 관찰 일수로 나눠 일평균 소비 개수를 구한다.
- 개봉형은 각 구매의 `구매 개수 × 당시 제품 용량`을 합쳐 활성 관찰 일수로 나눈다.
- 과거 구매에 용량이 없으면 현재 제품 용량을 사용한 것으로 추정한다.
- 과거 구매 용량 단위가 현재 제품과 다르면 그 기록은 용량 계산에서 제외한다.

### 6.3 소진 예측에 사용할 수 있는 추가 조건

구매량 기반 소비 통계를 현재 재고의 소진일 계산에 쓰려면 다음 조건을 모두 충족해야 한다.

- 현재 재고가 설정되어 있다.
- 실제 사용 기반 소진 예측이 없다.
- 사용할 수 있는 구매 기록이 3건 이상이다.
- 관찰 기간이 180일 이상이다.
- 용량 단위가 달라 제외한 기록 수가 사용할 수 있는 기록 수보다 많지 않다.
- 계산된 소비 속도가 0보다 크다.

조건을 충족하지 못하면 구매량 통계는 소진일의 강한 근거로 사용하지 않는다.

## 7. 계절 제품 계산

- 연중 사용은 활성 월 제한이 없는 상태로 저장한다.
- 특정 달에만 사용하는 제품은 활성 월을 한 달 이상 선택해야 한다.
- 소비 속도, 사용 주기, 소진일, 시즌 필요량, 세일 구매 추천에서 비활성 월의 날짜는 소비일로 세지 않는다.
- `사용 월 평균`은 실제 사용하는 달의 속도를 평균 30.4375일로 환산한 값이다.
- `연평균 월 환산량`은 1년 예상 소비량을 12개월로 나눈 비교용 값이다.
- `1년 예상 필요량`은 선택한 활성 월의 평균 일수를 합산해 계산한다.
- `사용 시즌 예상량`은 다음 연속 활성 구간에 필요한 양이다.

## 8. 소진 예측과 확인 필요 신호

### 8.1 소진일 근거

소진일에 사용할 수 있는 근거는 두 가지다.

- `실제 사용`: 완료 주기 또는 수량형 사용 기록
- `과거 구매량`: 충분한 기간과 표본을 갖춘 구매량 추정

과거 구매 간격으로 만든 날짜는 소진일이 아니라 `다음 구매 예상일`이다.

### 8.2 알림 기준

- 실제 사용 또는 과거 구매량으로 소진일을 계산할 수 있으면, 남은 일수가 제품의 알림 일수 이하일 때 확인 필요로 본다.
- 소진일을 계산할 수 없을 때만 현재 재고가 재고 알림 수량 이하인지 확인한다.
- 신뢰할 수 있는 소진일이 있는 동안에는 수량 기준 알림을 중복 적용하지 않는다.
- 직접 입력한 다음 세일일이 알림 기간 안에 들어오면 구매 확인 신호를 표시한다.
- 소진일 근거가 없고 다음 구매 예상일이 알림 기간 안에 들어오면 구매 확인 신호를 표시한다.

## 9. 월·연간 소비 통계

- 실제 사용 기록으로 소비 속도를 구할 수 있으면 그 값을 사용한다.
- 그렇지 않으면 6.1의 기본 조건을 만족하는 과거 구매량을 사용한다. 6.3의 더 엄격한 조건은 이 통계를 현재 재고의 소진일 계산에 사용할 때 적용한다.
- 개봉형의 용량 소비 속도는 `현재 제품 용량 ÷ 대표 1인 환산 주기`다.
- 수량형의 소비 속도는 최근 사용 기록으로 구한 `1단위당 예상 사용 일수`를 역산한다.
- 월평균은 평균 한 달 30.4375일, 연간은 365.25일을 기준으로 환산한다.
- 개봉형은 용량과 제품 개수를 함께 표시할 수 있다.

## 10. 다음 세일 구매 추천

다음 세일 구매 추천을 계산하려면 다음 값이 모두 있어야 한다.

- 다음 세일일
- 세일 때 확보하려는 개월 수
- 실제 사용 또는 과거 구매량으로 계산된 소비 속도

```text
세일일 예상 재고
= 현재 재고 - 오늘부터 세일일까지의 예상 소비량

추천 구매 수량
= 올림(세일일부터 목표 보유 종료일까지의 예상 소비량
     + 안전 재고
     - 세일일 예상 재고)
```

- 결과가 음수이면 0으로 본다.
- 계절 제품은 활성 월에 해당하는 날의 소비량만 포함한다.
- 추천 수량은 구매 개수 기준 정수로 올림한다.

## 11. 기록 날짜와 정정 규칙

### 11.1 날짜

- 업무 기록 날짜는 오늘 또는 과거만 허용한다.
- 소진일은 개봉일보다 빠를 수 없다.
- 개봉일과 소진일은 모두 사용 기간에 포함한다.
- 데이터베이스의 업무 기준 날짜는 Asia/Seoul을 사용한다.
- 날짜는 내부적으로 ISO 형식으로 저장하고 화면에서는 미국식 월/일/연도 형식으로 표시한다.

### 11.2 재고 원장 정정

- 입고 또는 수량형 사용 기록의 수량을 수정·삭제하면 그 시점 이후 재고 원장을 시간순으로 다시 계산한다.
- 같은 시각의 기록은 생성 순서를 유지한다.
- 재고 정정은 증감량이 아니라 그 시점의 실제 재고를 나타내는 절대 기준점이다.
- 원장을 다시 계산해 음수 재고가 생기거나 개봉·소진 순서가 성립하지 않으면 정정을 거부한다.

### 11.3 개봉·소진 주기 정정

- 진행 중인 개봉 기록의 개봉일과 사용 인원을 고치면 제품 상태와 연결된 개봉 이벤트를 함께 고친다.
- 완료된 사용 주기의 개봉일·소진일·사용 인원은 통계 근거로서 수정할 수 있다.
- 동일 제품에 개봉일과 소진일이 모두 같은 완료 주기를 중복 저장하지 않는다.
- 완료된 사용 주기를 수정하거나 삭제해도 이미 기록된 소진 이벤트와 재고 1개 차감은 되돌리지 않는다. 재고가 틀렸다면 재고 원장을 별도로 정정한다.

## 12. 제품 숨기기와 삭제

- 목록에서 숨기기는 모든 재고·사용·구매 기록을 유지한 채 기본 목록에서만 제품을 감춘다.
- 현재 개봉해 사용 중인 제품은 소진 처리 전까지 숨길 수 없다.
- 숨긴 제품은 다시 표시할 수 있다.
- 영구 삭제는 실제 사용·완료 주기·구매 기록이 없는 제품에만 허용한다.
- 최초 재고 기준 기록 하나만 있는 미사용 제품은 영구 삭제할 수 있다.
- 기록이 있는 제품은 삭제하지 않고 숨긴다.

## 13. 현재 모델의 한계

아래 항목은 확정 규칙이라기보다 현재 데이터 모델로 정확히 처리할 수 없는 범위다. 다른 문서와 코드를 정비할 때 별도 결정이 필요하다.

### 13.1 수량형 공동 사용은 인원 보정이 없다

수량형 사용 기록에는 사용 인원이 없다. 따라서 엄마와 함께 사용해 재고 감소가 빨라진 기간을 J님 한 명의 소비 속도로 되돌릴 수 없다. 현재 계산은 모든 수량형 사용 기록을 개인 소비로 간주한다.

### 13.2 과거 구매량에는 사용 인원 정보가 없다

과거 구매량 기반 소비 추정도 당시 사용 인원을 알 수 없다. 현재 계산은 재고 추적 전 구매량 전체를 개인 소비량으로 가정한다. 공동 사용 기간이나 비축 구매가 많았다면 추정치가 실제 개인 소비보다 커질 수 있다.

### 13.3 제품 한 개 안의 실제 잔량은 측정하지 않는다

개봉형 제품의 현재 잔량은 대표 사용 주기와 경과 인일로 추정한다. 병 안의 실제 ml를 직접 기록하는 모델은 아니다.

### 13.4 동시에 여러 개를 개봉하는 상황은 지원하지 않는다

개봉형 제품은 제품당 진행 중 주기를 하나만 둔다. 같은 제품 여러 개를 동시에 서로 다른 인원이나 장소에서 사용하는 상황은 표현할 수 없다.

### 13.5 구매와 입고를 자동 연결하지 않는다

어떤 구매가 어떤 입고로 이어졌는지 연결하는 식별자는 없다. 구매 이력과 재고 원장은 의도적으로 독립되어 있다.

## 15. 대표 확인 사례

규칙 변경 후 최소한 아래 사례를 다시 확인한다.

- 1L 제품을 2명이 약 1개월 사용하면 1인 주기가 약 2개월로 계산되는가.
- 1인 사용 주기와 2인 사용 주기가 섞여도 각 기록을 개별 환산한 뒤 중앙값을 구하는가.
- 같은 날 여러 구매가 구매 건수에는 모두 포함되고 구매 간격에는 하루로만 포함되는가.
- 실제 사용 기록이 생기면 과거 구매량보다 우선하는가.
- 구매 간격 통계는 실제 사용 기록이 있어도 모든 구매일로 계속 계산되는가.
- 구매 기록을 고쳐도 재고가 변하지 않고, 입고 기록을 고치면 이후 재고가 다시 계산되는가.
- 계절 제품의 비활성 월이 소비 기간과 구매 추천에서 제외되는가.
- 완료 주기를 삭제해도 재고 차감이 자동 복구되지 않는가.
