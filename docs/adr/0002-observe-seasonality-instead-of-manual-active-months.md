# 계절성은 수동 설정하지 않고 실제 사용에서 관찰한다

제품의 수동 `활성 월`을 제거하고, 연간 필요량은 실제 총소비량 또는 실제 소비 속도에서 계산하며, 계절성은 실제 기록의 월별 분포에서 자동 발견한다. 수동 월 설정은 J님이 예상한 시기와 실제 사용 시기가 어긋날 수 있고 한 번의 잘못된 설정이 사용 주기 전체를 무효화하는 반면, 자동 관찰은 입력을 늘리지 않고 실제 행동을 보존한다. 첫 완료 주기부터 기본 소비 추정을 시작하되 계절성은 상세 통계로 먼저 보여주고, 반복성이 확인될 만큼 충분한 관찰이 쌓인 뒤에만 소진일과 세일 구매 추천을 보정한다.

과거 구매 기록은 가격·구매처·구매 간격·비축 행동의 참고 자료로 남기지만 실제 소비량으로 간주하지 않는다. 정확히 아는 과거 사용 기록은 실제 사용 근거가 될 수 있으나 입력을 요구하지 않으며, 앱은 지금부터 관찰한 첫 실제 주기만으로도 임시 추정을 시작하고 이후 기록으로 스스로 보정한다.

앱이 직접 관찰한 실제 사용 기록은 첫 건부터 월별 상세 통계에 표시한다. 다만 계절성을 소진·세일 예측에 반영하려면 완전한 달력 12개월, 실제 소비 근거 2건 이상, 최고 연속 3개월 이동평균이 최저 이동평균의 2배 이상이라는 조건을 모두 충족해야 한다. 회상 소비 기준과 구매 기록은 이 판단에서 제외하며, 계절 보정은 연간 필요량 총합을 바꾸지 않고 월별 분포만 재배치한다.

이 결정은 현재 코드·UI·데이터베이스의 `active_months`와 과거 구매량 기반 소비 추정을 폐기 대상으로 만든다. 안전한 전환을 위해 먼저 새 데이터 기반을 기존 필드와 병행하고, 화면과 계산을 옮긴 뒤 별도 정리 migration에서 기존 필드를 제거한다.
